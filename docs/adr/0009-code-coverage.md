# 0009 — Code coverage

- **Status**: accepted
- **Date**: 2026-09-26

## Context

Pull requests should show which part of the code the tests exercise. CodeQL (ADR 0004) is static security analysis and says nothing about coverage. Everything stays local to the project: no data should leave GitHub Actions without a decision. The CI already builds with GCC on Ubuntu 24.04 (ADR 0004), and the domain is the part that must stay fully tested.

## Options considered

- **Instrumentation and report**
  - GCC `--coverage` with [gcovr](https://gcovr.com/) (BSD): one Python tool, reads the gcov data directly, produces HTML, JSON and text reports, and takes its filters from a config file shared by CI and local runs.
  - lcov + genhtml (GPLv2+): the classic pair, but Perl, two tools, and a separate filtering step.
  - Clang source-based coverage (`llvm-cov`): precise, but the CI and the dev container build with GCC.
- **Where the report goes**
  - GitHub Actions only: the job summary and a downloadable HTML artifact.
  - An external service (Codecov, Coveralls): pull request comments and history, but sends the code and its coverage to a third party.
- **Where it runs**
  - In the "Build and test" job: one build, but the instrumented build replaces the regular debug build that clang-tidy and the tests use, and the job gets longer.
  - In a separate "Coverage" job: a second build, in parallel, so the main check keeps its duration.
- **Threshold**
  - Fail below a minimum (for instance on `src/domain/`).
  - Report only.

## Decision

- A `MISIGN_COVERAGE` CMake option (GCC only), enabled by the `coverage` preset, compiles and links every target with `--coverage`.
- gcovr reports on `src/` only (`gcovr.cfg`): `tests/`, the files generated by moc, qmltc and rcc, and third-party code are excluded. Compiler-generated exception and unreachable branches are left out of branch coverage.
- A separate "Coverage" job in the pull request CI runs every test on the instrumented build, writes line and branch coverage per directory to the job summary (`scripts/coverage_summary.py`), and uploads the HTML report as the `coverage-report` artifact.
- No external service, and no threshold for now: most of the code is still to be written, and a minimum set this early would only be lowered again.

## Consequences

- Every pull request shows its coverage on the run page; the detailed report is one download away, with no third party involved.
- The CI builds the project twice per run, in parallel jobs: more Actions minutes, same wall-clock time.
- Nothing prevents coverage from dropping. A threshold, starting with `src/domain/`, can be added later with gcovr's `--fail-under-line` and `--fail-under-branch` once the domain is complete.
- There is no coverage history or pull request comment; getting one would take a new ADR.
- The gcovr version is pinned in `ci.yml` and in the dev container, and bumped by hand in both.
