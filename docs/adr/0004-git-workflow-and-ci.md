# 0004 — Git workflow and CI/CD

- **Status**: accepted
- **Date**: 2026-09-25

## Decision

- Two long-lived branches: `main` (production) and `dev` (development), both protected; merges only when CI is green.
- Work branches created from `dev`, named after the Linear issue (`feature/PHY-12-...`, `fix/PHY-20-...`), merged through pull requests.
- Conventional Commits, SemVer, changelog generated by release-please.
- All project content in English: documentation, code comments, commit messages, pull requests.
- GitHub Actions:

| Pipeline | Trigger | Steps | Result |
|---|---|---|---|
| CI | Pull request to `dev` or `main` | Format, lint, build, unit tests, integration tests | Merge blocked if a test fails |
| Dev deployment | Merge into `dev` | Windows and Linux builds, installers, GitHub pre-release | Test build |
| Prod deployment | Merge into `main` | SemVer tag, Windows and Linux builds, installers, stable GitHub Release with changelog | Public release |
| Maintenance | Weekly | Dependabot, CodeQL | Up-to-date dependencies, detected vulnerabilities |

- Project tracking in Linear: "Misign V1" project in the existing `PHY` team (the free plan is limited to two teams), linked to GitHub.

## Consequences

- Pull request CI runs on Linux to save minutes; Windows builds are reserved for merges into `dev` and `main`.
- Docker is only used for the development environment (dev container), never for CI or for the application itself.
